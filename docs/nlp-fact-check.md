# NLP seed fact check

Reviewed all 36 entries in [the NLP category seed](../data/classic/classic.nlp.seed.json) on September 30, 2026.
The evidence below uses publisher model cards, configurations, public repository history, original papers and release announcements.

## Interpretation

- Checkpoint entries describe the named checkpoint; family entries describe publisher variants, not every community fine-tune using the architecture
- Languages are documented languages or verified examples of a larger multilingual set, not an exhaustive inventory
- Classification, question answering, summarization and translation can require downstream fine-tuning; their task tags do not mean every base checkpoint provides a ready-to-use task pipeline
- Training datasets include documented pretraining, continued pretraining and embedding fine-tuning data; lists are not necessarily exhaustive and evaluation-only benchmarks are excluded
- `undisclosed` means no reliable named training corpus was established for this entry; it does not mean the publisher disclosed nothing about the training process
- Dates use checkpoint availability where established; family dates can identify the original paper or announcement
- A year is used where the exact first public checkpoint date is not established; repository creation dates and paper dates are not automatically checkpoint release dates
- Context records a published configuration or packaged input limit where available; it is not necessarily the sequence length used during training
- IDs, entry order and difficulty pools are game configuration and were preserved

## Regeneration and validation

Shared metadata corrections are also kept in the overlapping language-model source entries.
The backend consumes the merged classic seed; Timeline derives its catalog dates from that seed.
Regenerate and validate with the existing workflow:

```bash
pnpm classic-merge-to-one
pnpm timeline-merge-to-one
pnpm db:validate-seed
```
