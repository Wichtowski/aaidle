# Language model seed fact check

Reviewed on 2026-09-30 against provider specifications, original model cards, author repositories, and release announcements.
All 130 model IDs were reviewed and preserved.
The table records the corrections made by this audit, the evidence used, and model-specific limitations.
Previously applied NLP and computer-vision corrections were preserved.

## Interpretation

Capability fields describe the named API model or downloadable checkpoint, rather than every feature of the surrounding chat application.
For example, standard GPT-4o has text/image input and text output; separate audio and Realtime variants are different models.
The standard Grok 2 and Grok 3 API aliases are text-only, while Grok 2 Vision is a separate endpoint with a different context limit.
Release dates describe the first public introduction of the named model, including previews, rather than assuming an API snapshot date is the original release date.
Dates retained from the existing NLP audit keep that audit's checkpoint/family interpretation.
A year-only date avoids claiming an unsupported release day.
Command Light's original release date remains unknown: its 2023 rename and subsequent update do not prove when the underlying model first shipped.

`open` means publicly distributed weights under an open license, including attribution and copyleft requirements.
`restricted` covers noncommercial and custom model licenses, including Llama, Gemma, Cohere research releases, original DeepSeek V3/V2.5, and Moonshot's modified MIT terms.
A download registration gate alone does not make Apache-licensed Bielik weights proprietary.
API availability or private enterprise deployment does not establish downloadable open weights.
License information describes the named checkpoint; a later differently named checkpoint's license is not substituted.

`reasoningSupport` describes a dedicated thinking mode, rather than ordinary ability to solve reasoning problems.
`optional` means a documented switch can turn thinking off, even if thinking is enabled by default.
`native` is retained when the named reasoning model requires thinking.
`toolUse: null` means native tool calling was not established; generic agent benchmarks or an external wrapper alone do not prove it.

Language arrays contain names explicitly documented for the model or its release family and may be nonexhaustive.
Empty arrays mean that a supported-language inventory was not established; they do not mean the model cannot understand any language.
The existing `multilingual` family marker is retained for NLLB, XLM-RoBERTa, and multilingual BERT.
Vision and audio may support fewer languages than text, as noted for Llama Vision and Phi-4 Multimodal.

Context limits use exact provider specifications or published configuration values where available.
Qwen's native 32,768-token configuration is retained instead of silently assuming manually enabled YaRN scaling.
Rounded legacy limits advertised only as K/M are retained where an exact configuration is unavailable.
T5-family tokenizer/configuration budgets are not claims of an intrinsic attention architecture hard limit.
Gemini 1.0 Pro's unsubstantiated 32,760-token value is omitted.
Categories and use cases are curated game labels; they do not claim a vendor certification.

## Synchronization and validation

Shared changes to Bielik, FLAN-T5, and Qwen2.5-VL were synchronized into their other category shards so later merges cannot restore stale values.
The combined Classic catalog and Timeline catalog were regenerated using the repository scripts.
The unknown Command Light release date excludes that model from Timeline while keeping it in Classic.
No model IDs or pool memberships were removed from the language-model shard.

```bash
pnpm classic-merge-to-one
pnpm timeline-merge-to-one
pnpm db:validate-seed
pnpm check
```

When removing an optional field, the merge script's existing baseline can retain it during the first regeneration.
For the Gemini 1.0 Pro context removal, a temporary baseline with that field omitted was supplied as the merge script's fourth argument.
Subsequent standard merges preserve the omission because the combined baseline no longer contains that value.
